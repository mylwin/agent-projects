# 前端实施计划

以[系统架构](../../01-architecture/02-system-architecture.md)为目标，以[界面设计](../02-design/01-interface-design.md)和[数据契约](../03-data/01-data-contract.md)约束实现。本文说明实施顺序与能力边界，不保存逐轮校验结果。

## 1. 交互原型

当前已实现 React + TypeScript + Vite 前端，使用 Lucide 图标与独立 CSS，覆盖：

- 计划列表、新建、搜索、计划详情和日期切换。
- 活动编辑、路线高亮、助手侧栏收缩与手机切换。
- 独立对话、本地示例调整、自动版本、最终方案选择与返回提醒。
- 浏览器本地存储、历史恢复、保存失败提示及重试。

初始行程和助手示例分别直接读取数据目录中的 JSON，不维护第二份样本。当前助手使用明确的本地规则，地图为 SVG 概览。

## 2. 接入计划服务

在 `frontend/src/api/` 实现服务端访问与字段适配，按数据契约用正式行程读取替换初始样本入口。项目 ID、资源归属、版本与并发控制交由服务端处理，避免在页面与多个状态容器中重复维护同一份正式结果。

此阶段仍保留现有列表和详情路由。先接通计划读取、活动修改、版本历史和最终方案的持久化，再替换浏览器工作区存储。对应业务规则见[计划项目与助手](../04-features/01-plan-projects.md)及[最终方案选择](../04-features/02-final-selection.md)。

## 3. 接入真实助手与运行事件

用正式规划接口和 SSE 事件替换本地计时与规则演示。按运行 ID 和事件序号合并进度、失败、取消及待补充信息；已校验提交的行程才形成正式版本。保持目标日期的修改范围与历史快照不可变约束。

逐字回复显示应来自真实回复流，界面动效不代表真实推理证据。断线恢复及离开页面后的任务行为以服务端运行协议为准。

## 4. 接入地图与真实地点数据

按架构引入高德地图展示和路线服务，用稳定的地点 ID、经纬度、坐标系及来源信息替换 SVG 平面坐标。保留地图与活动的选中联动，明确区分估计费用与真实查询结果。

浏览器地图凭据按供应商要求管理；模型与地图 Web 服务密钥仅放后端，不编入前端。

## 5. 联调与部署

在接口与运行协议稳定后覆盖计划切换、刷新恢复、失败重试、历史版本与最终方案等主要路径，再处理 SPA 路由回退和 API/SSE 代理。真实后端、模型、地图及生产部署均待实施。

静态检查使用 `pnpm typecheck`、`pnpm lint`。检查脚本、日志、截图和实际结果按任务存入 `tmp/frontend/YYYY-MM-DD/<任务名>/`，不写入本目录。
