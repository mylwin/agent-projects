# 旅行计划项目与助手交互

## 页面与入口

- `/` 自动进入 `/plans`「我的旅行计划」。
- `/plans` 展示计划文件夹、最近制定的结果、版本数量和对话数量，支持搜索与新建。
- `/plans/:id` 是计划详情，行程和助手始终绑定同一个项目 ID。
- `/plans/:id?revision=:revisionId` 查看历史结果。历史行程只读，可返回当前计划继续编辑与对话。
- 无效项目链接提供返回入口；生产静态服务器需要把这些前端路由回退到 `index.html`。

每个文件夹最多预览最近两份结果，固定预留两行高度，保持同一行卡片底部对齐；进入详情后可通过版本选择器查看全部结果。成功的示例调整会保存新的独立快照，并在对应助手消息下给出结果入口；同一计划的历次对话都留在该项目中。

用户可在详情底栏将正在查看的任一版本「选为最终方案」。选定后，列表封面、名称和「查看方案」默认进入该快照；「继续规划」进入最新可编辑行程。继续调整不覆盖已经选定的最终方案，也不妨碍稍后重新选择。

返回列表或离开当前计划时，若正在查看的版本尚未被选为最终方案，显示一次选择提醒。可「选定并返回」，或稍后选择、保留原方案直接返回；关闭提醒留在原页。浏览器前进、后退经过相同检查，计划内部切换版本不打断。正在查看已选定的最终方案时直接返回，不重复提醒。保存失败会留在提醒中供重试，不强行跳转。

## 「项目文件夹」的数据含义

当前为浏览器内的逻辑项目文件夹，并非用户磁盘上的真实目录。存储键为 `tripweave:workspace:v2`，结构是 `{ version: 2, projects: PlanProject[] }`。

| 字段 | 用途 |
| --- | --- |
| `id`、`name` | 独立项目标识和用户输入的计划名称 |
| `createdAt`、`updatedAt` | 创建与最近更新时间 |
| `trip` | 当前可编辑行程，与最新自动记录的快照对应 |
| `messages` | 该计划独立的完整对话历史 |
| `requests` | 该计划尚待处理的调整要求 |
| `revisions` | 已制定结果；每项保存 ID、版本号、标题、时间与独立行程快照 |
| `draft` | 兼容旧版未归档修改；新编辑完成后自动归档，设为 false |
| `finalRevisionId` | 用户选定的最终版本 ID；未选定为 null |
| `pending` | 中断或正在进行的调整指令及目标日期，用于返回后继续 |

`Message.revisionId` 是可选结果引用，供对话中的「查看这次的行程结果」使用。版本不是当前行程对象的共享引用，后续修改不改变旧版快照。

手动修改、用户消息和处理结果会自动写入项目存储。手动提交活动编辑或助手完成有效调整时，自动归档为新版本；没有变化不重复制造版本。界面不再提供「保存版本 / 保存结果」按钮。「选为最终方案」只更新指向已有版本的标记，不复制行程、不新增版本。存储异常时保留内存内容，顶部显示重试入口，不能把未落盘状态当作已可靠保存。

旧 v2 项目缺少 `finalRevisionId` 或引用无效版本时，读取为 null，保留全部行程、对话及快照。若旧项目仍有 `draft`，直接选定当前行程时会先归档这份旧修改，再将其设为最终方案。

旧的 `tripweave:journal:v1` 单行程记录在首次读入时迁移为第一个项目；旧键保留。默认初始计划使用稳定 ID，避免刷新后深链接失效。新工作区发生损坏时不删除原数据，回退到初始样本并显示读取问题。

当前不提供跨设备同步、多标签页并发合并或服务端用户隔离；未来由后端项目 ID、身份归属与事务接管这些职责。

## 助手侧栏

详情顶部只保留品牌和出行信息入口，移除「自动记录」等常驻提示。返回全部计划的入口移到正文面包屑；目的地、人数与预算在行程标题展示，不再重复挤占导航。出行信息弹窗按目的地与同行概况、旅行日期、两项费用、出发确认事项排列；日期和费用使用较大字号，支持关闭按钮、Escape 与点击遮罩关闭，不再增加确认按钮。最新说明和截图见 [03-return-and-trip-info.md](03-return-and-trip-info.md)。

- 中部按钮点击收起或展开；收起后留窄边栏，主行程区域扩大。
- 鼠标在收起的侧栏内连续停留 1000ms 后展开，提前移开会清除计时。
- 展开后不会因鼠标离开自动收起，避免输入时抖动。
- 收起期间当前处理可以继续；隐藏内容设置为 inert，避免键盘误入不可见控件。
- 手机用「我的行程 / 旅行助手」切换，不再叠加桌面悬浮箭头，也不依赖悬停手势。
- 顶部导航与底部输入区继续固定，只有行程与消息独立滚动。

## 简洁输入、示例与动效

输入区为单行输入框和发送按钮，不再显示「编辑行程」标题或大段说明。上方提供三个可点选的例子，来自 [03-assistant-examples.json](../03-data/03-assistant-examples.json)：轻松节奏、清淡午餐、餐饮预算。

发送后立即展示用户输入，经历「整理想法 → 调整安排 → 回复逐字出现」三种状态；按钮可停止本次调整。减少动态效果模式下回复直接显示。处理中的活动编辑与重复发送被限制，避免同时改写结果。

这仍是**本地规则演示，未接入大模型**：

- 轻松节奏：把当天一个固定活动改为自由时光，路线距离标记待核实。
- 清淡午餐：更新当天午餐标题及笔记。
- 餐饮预算：按人数修改餐饮估计，仍需用户核实真实价格。
- 不支持的表达或明显否定指令只保留在待处理清单，不伪造完整理解或成功修改。
- 没有实际变化时不重复创建结果版本。

离开计划或切换到其他计划时，取消该页面尚未完成的演示计时，保留用户消息与 `pending`。再次进入可点击「继续调整」。异步结果按项目 ID 提交，不能写进另一份计划。

## 新建计划的范围

当前从苏州旅行样本创建独立项目，可自定义名称、日期、1–3 天、人数及全团预算。目的地固定为苏州，不把已有苏州地点冒充成其他城市的行程。后续接入真实 Planner 后，再增加任意目的地生成能力。

## 后端演进

将项目存储替换为服务端项目、会话和版本接口，保留现有 URL 与项目 ID 绑定关系。把本地演示阶段替换为真实 SSE 事件，把逐字效果替换为真实回复流。阶段、思考、回复和工具事件分开处理：思考过程默认折叠且不持久化，正式回复以最终持久化消息为准。只有后端提交的正式结果才能创建版本引用；界面的处理动效不代表真实推理证据。
