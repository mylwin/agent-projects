# 自动记录与最终方案选择

日期：2026-11-03。沿用暖白酒红的旅行日笺设计，按最新四张批注图精简操作。

> 本文说明自动版本与最终方案的首轮设计。之后移除了自动记录提示、增加返回选择提醒并重新设计信息弹窗，最新状态见 [03-return-and-trip-info.md](03-return-and-trip-info.md)。

## 当前交互

- 移除顶部「保存版本 / 保存结果」。有效的活动编辑、助手调整自动生成独立快照；已提交消息继续自动保留。
- 底栏使用「选为最终方案」，把当前查看的版本标记为计划结果。已选中的版本显示「已选定」，不重复生成版本。
- 可选择任一历史版本；继续调整只产生新结果，不自动替换最终方案。列表封面和「查看方案」进入最终快照，「继续规划」进入最新行程。
- 计划卡片固定预留两条结果的位置，最多展示两版；其余版本在详情选择器中查看。
- 导航只保留品牌、自动记录提示与出行信息。返回计划列表移入正文面包屑，旅行元信息保留在行程标题。
- 出行信息弹窗分为旅程概况、日期与费用、出发提醒，移除重复的底部确认按钮。

固定导航、模糊透明效果、侧栏收缩和助手输入方式沿用已有设计。按钮沿用按压反馈，选定后状态即时更新并出现提示；弹窗沿用短距离进入，尊重减少动态效果设置。

## 数据兼容与失败处理

项目新增 `finalRevisionId: string | null`，保持原 `tripweave:workspace:v2` 存储键与版本。旧项目缺失或引用不存在的最终版本时恢复为 null，保留历史。旧版未归档草稿在被选作最终方案时先归档，避免遗失修改。

存储失败时保留内存中的行程与选择，显示保存失败及重试入口；重试成功才写入浏览器持久存储。数据仍仅在当前浏览器，真实 Agent、后端与跨设备同步尚未接入。
